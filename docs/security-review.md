# Безопасность ядра (CR-16): чек-лист внутреннего ревью и находки

Внешнего аудита нет (O8): E2EE — «бета», пока чек-лист не пройден на этапе 6 и не прогнаны T1–T19 на стенде
(CR-15). Этот файл — сам чек-лист (раздел 1), что уже сделано в коде (раздел 2) и что сознательно принято
(раздел 3). Отличия протокола от Matrix — `docs/protocol.md`; решения — ADR 0001 и дополнения A1–A4.

## 1. Чек-лист ревью (этап 6)

> С блока 5A чек-лист и записи проходов — `docs/review-checklist.md` (проход 1 — 2026-10-18, находки R1–R2,
> открытые O-1…O-8). Ниже — исходный список CR-16, оставлен для истории.

Каждый пункт — «прочитано, тест есть, вывод записан». Ссылки — на модули `crates/stoat-crypto/src/`.

**Адаптер (CR-20, `machine.rs`, `requests.rs`, `ids.rs`)**

- [ ] Ни один ruma-тип не выходит в публичный API (`types.rs`, `lib.rs` — только свои типы).
- [ ] Правила ADR 0001: to_device по одному; `get_missing_sessions(∅)` в каждом проходе; трекаются я и все
      участники; `sender_key` не уходит в конверт, `device_id` — подсказка (`Mismatch`).
- [ ] Таблица ошибок `map_megolm_error` полна; перенос сообщения сервером → `ChannelMismatch` или ожидание
      ключа, никогда не «обычное сообщение».
- [ ] Обнаружение перенесённого сообщения сканирует **не более 512 каналов** (`MAX_CHANNEL_SCAN`), дальше —
      см. 3.2.
- [ ] Щит (`decrypt`): ключ из бэкапа/пересылки — не выше `Unauthenticated`; проверенным считается только
      устройство с локальным доверием после SAS.

**Привязка к контексту (CR-19, `binding.rs`)** — replay, правки, ответы; границы таблиц и цена их вытеснения
(ADR A1, см. 3.1).

**Хранилище и ключ хоста (CR-09, CR-17, `store.rs`, `lock.rs`)**

- [ ] Ключ хранилища — 32 байта от платформы, `Zeroizing`, `Debug` скрыт; ядро его не сохраняет.
- [ ] Файловый замок до открытия SQLite; `destroy` — только под замком; второй экземпляр → `StoreLocked`.
- [ ] Свои значения в `custom_value` (`stoat.*`) шифруются `StoreCipher`, как всё хранилище.

**Ящик to_device (C2, `machine.rs`, `outbox.rs`, `batch.rs`)**

- [ ] Множество обработанных id коммитится в одной транзакции с крипто-изменениями; дубли — до библиотеки.
- [ ] Повторы при полном ящике ограничены (8 попыток, ≤ 256 в очереди); `undelivered_devices` в UI.
- [ ] Запросы ключей (`gossip.rs`): `request_room_key` — **только** при своём проверенном устройстве, после
      паузы, не для отозванных (`withheld`) и не для сессий чужого канала (ADR A2, см. 3.3).

**SAS (CR-11, `verification.rs`)**

- [ ] Протокол — библиотеки (commitment в `accept`, `hkdf-hmac-sha256.v2`, MAC ключей устройства); свой код
      только переводит состояния. Автопринятие `start` — только внутри запроса, который пользователь принял.
- [ ] `Done` даёт `LocalTrust::Verified` ровно одному устройству собеседника; `mismatch` → никто не проверен
      (тест `sas_mismatch_cancels_and_trusts_nothing`).
- [ ] Таймауты срабатывают без таймеров ядра: `wakeup_in_ms` ≤ 10 с при открытом потоке.

**Бэкап и секретное хранилище (CR-12, `backup.rs`)**

- [ ] Ключ бэкапа случаен; в секретном хранилище только шифротекст (`aes-hmac-sha2`, имя секрета в HKDF).
- [ ] Включение бэкапа с сервера — только если публичный ключ версии совпал с ключом из секрета
      (`BackupKeyMismatch`); 404/409 при загрузке — остановка, а не переход на чужую версию.
- [ ] PBKDF2 с сервера ограничен (≤ 1 000 000 раундов) до вычисления.
- [ ] Восстановленные ключи — `Unauthenticated`; импорт не ухудшает существующую сессию (правило «лучше»).

**Вложения (CR-10, `attachments.rs`)**

- [ ] Новый ключ и IV на каждый файл и миниатюру; младшие 64 бита IV нулевые.
- [ ] Хеш шифротекста сравнивается за константное время **до** появления первого байта открытого текста
      (`AttachmentVerifier` → `AttachmentDecryptor`).

**FFI и паники (CR-13)**

- [ ] В ядре и `proto` нет `unwrap/expect/panic!` вне тестов (`deny` в `lib.rs`); `encrypt_room_event_raw`
      обёрнут в `catch_unwind`.
- [ ] Каждый экспорт UniFFI ловит панику (`panic = "unwind"` в release, UniFFI → исключение Kotlin).
- [ ] Ошибки — плоские коды (`CryptoError::code`), `Display` без ключей и текста.

**Логи и диагностика** — ядро не логирует. Библиотека пишет через `tracing`; хост не включает уровень ниже
`warn` для `matrix_sdk_crypto` в релизных сборках. Sentry выключен.

**Зависимости** — `cargo deny check` (лицензии, advisories, источники) в CI; пины `=0.19.1`; RustCrypto,
`rand 0.10`, `bs58` — ровно те версии, что уже тянет библиотека (новых крейтов в графе нет).

**Fuzz** — `fuzz/`: конверт, payload, `/e2ee/*`, ключ восстановления (ночной прогон, `fuzz.yml`).

## 3. Принятые ослабления

1. **Вытеснение таблиц CR-19 (ADR A1).** Повтор (session, index) из вытесненной сессии (> 2048 сессий) и
   откат правки вытесненного сообщения (> 512 правленых на канал) больше не помечаются. Первый увиденный
   `message_id` считается оригиналом.
2. **Перенос сообщения ищется в ≤ 512 каналах.** У аккаунта с бо́льшим числом зашифрованных каналов
   перенесённое сообщение может остаться «ожидает ключ» вместо «подозрительно»; текст всё равно не
   показывается (своё устройство на запрос ключа чужого канала не ответит).
3. **Запросы ключей — только к своим проверенным устройствам (ADR A2).** Без проверенного своего устройства
   потерянный ключ возвращается только из бэкапа.
4. **Бэкап v1 подделываем** любым, кто знает публичный ключ (включая сервер): ключи из бэкапа и пересланные —
   `Unauthenticated` в UI (ADR 0001).
5. **Пароль восстановления — PBKDF2-SHA512, 500 000 раундов** (формат Matrix, не Argon2). Сервер хранит
   описание ключа и зашифрованный секрет, поэтому слабый пароль перебирается офлайн. UI: ключ
   восстановления по умолчанию, пароль — только с проверкой стойкости.
6. **Ключ секретного хранилища хранится на устройстве** (`stoat.recovery.v1`, под `StoreCipher`) — чтобы
   ротация бэкапа не спрашивала ключ снова. Компрометация устройства и так раскрывает ключ бэкапа и сессии.
7. **Таймауты SAS — библиотеки:** запрос 10 мин, SAS 5 мин целиком и 1 мин на шаг (план: 10 мин / 1 мин);
   проверка — при проходе раз в ≤ 10 с.
8. **Паники внутри библиотеки** ловятся на границе FFI (CR-13), а не вокруг каждого вызова; исключение —
   `encrypt_room_event_raw` (известная паника без общего ключа).
9. **Метаданные вложений**: размер шифротекста и число файлов (миниатюры в открытом `attachments`, C9)
   видны серверу.
10. **Фейковый сервер ≠ бэкенд.** Сценарии 3C проверены на `stoat-crypto-fakeserver`; против живого бэкенда —
    testkit (CR-15).
